📚 Vad är Git och GitHub?

Git (Versionshantering)

Git är ett versionshanteringssystem som låter dig:

  • Spara historik över alla ändringar i ditt projekt
  • Gå tillbaka till tidigare versioner
  • Arbeta med olika versioner parallellt (branches)
  • Se vem som ändrat vad och när

GitHub (Remote Repository)

GitHub är en molntjänst som:

  • Lagrar dina Git-repositories online
  • Gör det möjligt att dela kod med andra
  • Fungerar som backup för din kod
  • Tillhandahåller verktyg för samarbete

🎯 Viktiga Git-begrepp

Repository (Repo)

En mapp som Git övervakar. Innehåller alla dina filer plus en dold .git-mapp med historik.

Commit

En "ögonblicksbild" av ditt projekt vid en viss tidpunkt. Varje commit har ett meddelande som beskriver ändringen.

Remote

En version av ditt repository som finns på en server (t.ex. GitHub). Kallas ofta "origin".

Push

Skicka dina lokala commits till remote repository (GitHub).

Pull

Hämta ändringar från remote repository till din lokala dator.

Branch

En parallell version av koden där du kan arbeta utan att påverka huvudversionen (main/master).

🛠️ Steg-för-steg: Skapa lokalt och remote repository

1Förberedelser

Kontrollera att Git är installerat:

git --version # Ska visa något som: git version 2.x.x

Konfigurera Git (om inte redan gjort):

git config --global user.name "Kent Lundgren" git config --global user.email "lundgren.kent@gmail.com" # Kontrollera konfigurationen: git config --list

2Skapa .gitignore-fil

En .gitignore-fil talar om för Git vilka filer som INTE ska versionshanteras.

Varför .gitignore?
Vissa filer ska inte laddas upp till GitHub:
  • Temporära filer
  • Känslig information (lösenord, API-nycklar)
  • Stora filer som genereras automatiskt
  • OS-specifika filer (t.ex. Thumbs.db på Windows)

Exempel på innehåll i .gitignore:

# Windows specifika filer Thumbs.db Desktop.ini # Backup-filer *.bak *~ # Temporära filer *.tmp *.temp

3Initiera lokalt Git-repository

Navigera till projektmappen och initiera Git:

# Navigera till projektmappen cd D:\VåraFiler_primära_på_SSD\Kent_dokument\Data\HTML\kentlundgren_se\program\Bjerred\medlemmar # Initiera Git-repository git init # Skapar en dold .git-mapp som innehåller all versionshistorik
✅ Resultat: Du har nu ett lokalt Git-repository!

4Lägg till filer (Staging)

Innan du kan commita måste du "stage" filerna (lägga till dem i staging area):

# Se status på alla filer git status # Lägg till ALLA filer git add . # ELLER lägg till specifika filer git add index.html git add medlemmar.html # Kontrollera vad som är staged git status
Staging Area: En mellanstation där du samlar de ändringar du vill inkludera i nästa commit.

5Skapa första commit

Spara en ögonblicksbild av projektet:

git commit -m "Initial commit: Bjerred medlemshanteringssystem" # -m betyder "message" - alltid skriv ett beskrivande meddelande!
⚠️ Viktigt: Skriv alltid tydliga commit-meddelanden som beskriver VAD du ändrat och VARFÖR.

Exempel på bra commit-meddelanden:

  • "Lagt till sökfunktion för medlemmar"
  • "Fixat bug i datumformatering"
  • "Uppdaterat medlemsdata med nya medlemmar"

7Koppla lokalt repo till GitHub (Remote)

Efter att du skapat repositoryt på GitHub, koppla ihop det med ditt lokala repo:

# Lägg till remote (GitHub-adressen) git remote add origin https://github.com/kentlundgren/Bjerred-medlemmar.git # Kontrollera att remote är tillagd git remote -v # Ska visa: # origin https://github.com/kentlundgren/Bjerred-medlemmar.git (fetch) # origin https://github.com/kentlundgren/Bjerred-medlemmar.git (push)

8Byt till main-branch (om nödvändigt)

GitHub använder "main" som standardbranch, men Git kan skapa "master":

# Kontrollera vilken branch du är på git branch # Om du är på "master", byt till "main" git branch -M main
📖 Master vs Main - Historik och förklaring:

Historiskt (före 2020):
Git använde "master" som standardnamn för huvudbranchen när man körde git init.

Nu (efter 2020):
På grund av inkluderingsskäl har branschen gått över till att använda "main" istället för "master".
  • GitHub: Använder "main" som standard för nya repositories sedan oktober 2020
  • Git (lokal): Vissa versioner skapar fortfarande "master" som standard
  • GitLab, Bitbucket: Använder också "main" numera
Vad ska du göra?
För att undvika förvirring, använd alltid "main" för nya projekt. Om Git skapar "master", byt till "main" med kommandot ovan.

Ändra Git's standardbranch-namn permanent:
# Gör så att Git alltid skapar "main" istället för "master" git config --global init.defaultBranch main

9Pusha till GitHub

Nu ska vi skicka upp all kod till GitHub:

# Första gången: pusha och sätt upstream git push -u origin main # -u (--set-upstream) gör att framtida push/pull kan göras med bara "git push"

📖 Användbara Git-kommandon

Visa historik

# Visa commit-historik git log # Kompakt vy med en rad per commit git log --oneline # Grafisk vy av branches git log --oneline --graph --all

Ångra ändringar

# Ångra ändringar i en fil (innan add) git restore index.html # Ta bort fil från staging (efter add, innan commit) git restore --staged index.html # Ändra senaste commit-meddelandet git commit --amend -m "Nytt meddelande"

Branches

# Visa alla branches git branch # Skapa ny branch git branch ny-funktion # Byt till en branch git checkout ny-funktion # Skapa OCH byt till ny branch git checkout -b ny-funktion # Merga branch till main git checkout main git merge ny-funktion

Hämta ändringar från GitHub

# Hämta och merga ändringar git pull # Bara hämta (utan att merga) git fetch

💡 Bra att veta

Gör små, frekventa commits istället för stora sällsynta. Det gör det lättare att:

  • Förstå vad som ändrats
  • Hitta när en bug introducerades
  • Ångra specifika ändringar

Skriv bra commit-meddelanden

Format:

# Kort sammanfattning (max 50 tecken) git commit -m "Lagt till sökfunktion" # Med längre beskrivning git commit -m "Lagt till sökfunktion Användare kan nu söka medlemmar på namn, medlemsnummer eller datum. Sökningen är case-insensitive och söker i realtid."

.gitignore är viktig!

Lägg alltid till en .gitignore INNAN du gör första commit. Det förhindrar att oönskade filer laddas upp.

🚨 Vanliga problem och lösningar

Problem: "fatal: not a git repository"

Lösning: Du är inte i en Git-mapp. Kör git init eller navigera till rätt mapp.

Problem: "fatal: remote origin already exists"

Lösning: Remote finns redan. Ta bort och lägg till igen:

git remote remove origin git remote add origin https://github.com/kentlundgren/Bjerred-medlemmar.git

Problem: Push nekad - Permission denied / Authentication failed

Exempel på fel:

remote: Permission to kentlundgren/Bjerred-medlemmar.git denied to lundgren9. fatal: unable to access 'https://github.com/...': The requested URL returned error: 403

Orsak: Git försöker använda fel GitHub-konto (t.ex. "lundgren9" istället för "kentlundgren") för att pusha. Detta händer när Windows har sparat gamla inloggningsuppgifter.

🔐 Hur Git-autentisering fungerar i Windows:

1. Första gången du pushar:
Git ber dig logga in på GitHub (vanligtvis via en popup i webbläsaren).

2. Windows sparar dina credentials:
Efter lyckad inloggning sparar Windows dina autentiseringsuppgifter i Windows Credential Manager (Autentiseringshanteraren på svenska) under namnet: git:https://github.com

3. Framtida push-kommandon:
Git använder automatiskt de sparade credentials - du behöver inte logga in igen.

⚠️ Problemet: Om du har flera GitHub-konton eller gamla credentials, kan Git använda fel konto!

Se bild: Windows Credential Manager med sparade Git-credentials

Lösning 1: Rensa Windows Credential Manager (Rekommenderas för att byta konto) ✅

  1. Tryck på Windows-knappen och sök efter: "Autentiseringshanteraren" eller "Credential Manager"
  2. Klicka på "Windows-autentiseringsuppgifter" (Windows Credentials)
  3. Leta efter poster som börjar med "git:https://github.com" (se bild ovan)
  4. Klicka på pilen för att expandera posten
  5. Klicka på "Ta bort" (Remove)
  6. Försök pusha igen: git push -u origin main
  7. Du får nu en ny inloggningsprompt - logga in med rätt konto (kentlundgren)
⚠️ Viktigt: När du tar bort credentials och pushar igen kommer Windows automatiskt att skapa NYA credentials efter att du loggat in. Dessa nya credentials sparas permanent tills du tar bort dem igen.

Lösning 2: Lägg till det andra kontot som Collaborator 👥

Om du har två GitHub-konton (t.ex. "kentlundgren" och "lundgren9") och vill att båda ska ha tillgång till repositoryt, kan du lägga till det andra kontot som collaborator:

Steg för att lägga till collaborator:

  1. Gå till ditt GitHub-repository: https://github.com/kentlundgren/Bjerred-medlemmar
  2. Klicka på Settings (längst till höger i menyn)
  3. Klicka på Collaborators i vänstermenyn under "Access"
  4. Klicka på "Add people"
  5. Skriv användarnamnet (t.ex. "lundgren9") och klicka "Add [username] to this repository"
  6. Den andra användaren får en invitation via email och måste acceptera den

Se bild: Collaborators-sidan på GitHub

Acceptera collaborator-invitation:

  1. Logga in på GitHub med kontot som blev inbjudet (t.ex. lundgren9)
  2. Du kommer se en notifikation om invitation
  3. Gå till repositoryt eller klicka på notifikationen
  4. Klicka på "Accept invitation"
  5. Nu har både "kentlundgren" och "lundgren9" push-rättigheter!

Efter att invitation accepterats:

# Nu kan du pusha utan problem! git push -u origin main # Git kommer använda lundgren9's credentials och det fungerar nu # eftersom lundgren9 är collaborator
📌 När ska du använda Collaborators?
  • ✅ Du har två separata GitHub-konton som båda behöver push-access
  • ✅ Du arbetar i team och andra personer ska kunna pusha
  • ✅ Du vill ge någon annan rättigheter att ändra i repositoryt
När ska du INTE använda Collaborators?
  • ❌ Du vill byta från ett konto till ett annat permanent
  • ❌ "lundgren9" är gamla/felaktiga credentials som inte längre ska användas
I ditt fall: Om både kentlundgren och lundgren9 är dina konton, är collaborator-lösningen perfekt! Om lundgren9 bara är gamla credentials, använd Lösning 1 (rensa Credential Manager) istället.

Problem: Ser filer från andra projekt i Cursor/IDE

Orsak: Det finns ett Git-repository i en överliggande (parent) mapp som inkluderar flera projekt.

⚠️ Viktigt att förstå: Nested Git Repositories

Om du har följande struktur: 
D:/
└── kentlundgren_se/           ← Git repo här
    ├── .git/
    ├── program/
    │   ├── projekt1/
    │   ├── projekt2/
    │   └── Bjerred/
    │       └── medlemmar/      ← Vill ha separat Git repo här
    │           └── .git/
Då kan det bli förvirrande! Det överliggande repositoryt (kentlundgren_se) kan "se" alla ändringar i alla undermappar.

Lösningar:

Lösning 1: Öppna bara projektmappen i din IDE (Rekommenderas!) ✅

  1. I Cursor/VS Code: File → Open Folder (eller Ctrl+K Ctrl+O)
  2. Välj BARA medlemmar-mappen:
    D:\VåraFiler_primära_på_SSD\Kent_dokument\Data\HTML\kentlundgren_se\program\Bjerred\medlemmar
  3. Nu kommer Cursor bara fokusera på detta projekt och dess Git-repository

Lösning 2: Lägg till i .gitignore i överliggande repo

Om det överliggande repositoryt ska fortsätta existera, lägg till medlemmar-mappen i dess .gitignore:

# I D:/kentlundgren_se/.gitignore program/Bjerred/medlemmar/

Lösning 3: Använd Git Submodule (Avancerat)

För avancerade användare som vill ha separata repositories men ändå länka dem:

# I det överliggande repositoryt git submodule add https://github.com/kentlundgren/Bjerred-medlemmar.git program/Bjerred/medlemmar
💡 Best Practice: För separata projekt som inte är relaterade till varandra, håll dem i helt separata mappar utanför varandra, eller använd Lösning 1 (öppna bara projektmappen i din IDE).
